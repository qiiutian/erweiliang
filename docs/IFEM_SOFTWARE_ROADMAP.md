# iFEM 重构软件总体路线图

> 当前进度（2026-08-10）：阶段 0 和阶段 1 的核心基线已完成。
> 阶段 2 已支持二维/三维建模空间、直线与解析圆弧混合路径、无分支空间折线梁、
> 三维坐标编辑、五类统一截面及真实截面扫掠、三维几何预览和梁测点环向/方向角可视化。
> 阶段 3 已支持在三维真实梁表面创建、拖动、复制、对侧布置和等距阵列测点；
> 算法能力匹配、自适应参数面板、插件恢复与字段级校验已完成；
> 下一纵向切片为几何/分析网格分离与重离散测点恢复，样条曲梁和实时数据链路随后推进。

## 1. 产品目标

构建一套可独立安装、可交互建模、可布置测点、可接入多种逆有限元算法，
并能够离线或实时显示形状、应变和应力结果的桌面软件。

首个完整版本覆盖以下闭环：

1. 创建或导入结构模型。
2. 设置材料、截面、边界条件和离散方式。
3. 在二维或三维模型上交互布置测点并映射数据通道。
4. 选择算法、配置参数、校验输入并运行计算。
5. 查看形态、应变、应力、误差和时间历程。
6. 保存项目、恢复工作状态并导出结果。

## 2. 技术路线

### 2.1 桌面工作台

- 保留 PySide6 和 Qt Widgets，使用 `QMainWindow + QDockWidget` 构建可停靠工作区。
- 中央区域始终保留二维/三维视口，左右两侧使用上下文属性面板，底部放置数据和时间轴。
- 建模、测点、分析和结果采用工作模式，而不是继续向单个表单页面追加控件。
- 使用命令模式和 `QUndoStack` 管理新增、移动、删除、批量布置等可撤销操作。

### 2.2 建模与网格

- 内置结构前处理器首先支持节点、直梁、折线梁、样条曲梁、截面和材料。
- 结构几何与计算网格分离；测点附着到几何实体，不直接依赖易变化的网格编号。
- 第二阶段接入 Gmsh Python API，负责曲线/曲面网格以及 STEP、IGES、MSH 等格式。
- 不从零实现完整机械 CAD，也不把某个外部 CAD 软件的界面作为算法运行前提。

### 2.3 测点与数据

- 测点使用稳定 UUID，并保存几何实体 ID、局部坐标、截面环向角、表面内测量轴角、全局轴向量、量长和通道 ID。
- 梁测点使用曲线参数坐标；壳测点使用曲面参数或单元重心坐标，并保存法向和方向。
- 支持点击添加、拖动、复制、镜像、上下表面对、等距阵列和批量导入。
- 测点布置与测量值分离：同一个布置可以加载 CSV、文件回放或实时数据帧。

### 2.4 算法插件

- 所有算法通过统一协议声明元数据、能力、参数模式、校验方法和求解方法。
- UI 根据算法能力动态启用几何、测点、边界条件和参数选项。
- 算法只能接收领域层 `AnalysisContext`，不能直接读取 Qt 控件或操作 VTK Actor。
- 现有二维梁表面应变积分算法作为第一个内置插件，公式和求解过程保持不变。
- 后续大变形、三维梁、曲梁、壳和其他 iFEM 方法通过注册新插件接入。

### 2.5 结果与实时显示

- 统一结果对象保存位移、转角、应变、应力、自定义场、单位、分量和关联位置。
- 可视化层只消费结构模型和结果帧，不了解具体求解器类型。
- 实时模式通过不可变测量帧和结果帧传递数据，求解放到工作线程或独立进程。
- VTK 场景中的网格和 Actor 尽量复用，只更新坐标和数据数组，避免重复创建场景。

### 2.6 项目和文件

- 使用版本化 `.ifemproj` 项目包。
- `project.json` 保存模型语义、测点、工况、算法 ID、参数和界面状态。
- VTP/VTU 保存大型网格，HDF5 保存长时间序列，缩略图用于最近项目页面。
- 内部统一使用 SI 单位，界面显示单位独立配置。
- 每次格式变更提供显式迁移函数，继续兼容当前 JSON 配置。

## 3. 目标模块边界

```text
ifem/
  domain/          纯领域类型、项目模型、算法协议、结果协议
  application/     项目命令、求解调度、任务和数据流服务
  algorithms/      内置算法插件及第三方算法适配器
  modeling/        几何编辑、网格、拾取、吸附和 CAD 导入
  visualization/   场景、图层、拾取反馈、探针和时间动画
  infrastructure/  项目文件、设备、网络、日志和插件发现
  ui/              Qt 主窗口、停靠面板、属性编辑器和对话框
```

当前顶层模块在功能稳定后逐步迁入这些目录，不执行一次性大规模重写。

## 4. 分阶段交付

### 阶段 0：稳定基线

- 保存路线图、开发说明和依赖启动方式。
- 为当前示例保存数值回归基线。
- 保证算法重构前后节点自由度结果一致。
- 建立每次提交必须通过的测试命令。

### 阶段 1：核心分层

- 建立算法协议、能力声明、注册中心和分析服务。
- 把现有算法包装成插件，保留旧函数作为兼容入口。
- 建立 `ProjectDocument`、项目变更状态和版本字段。
- 将窗口中的求解调度逐步迁入应用服务。

### 阶段 2：交互建模 MVP

- 新建项目与建模工作区。
- 创建、选择、移动和删除节点。
- 创建直梁、折线梁和样条曲梁。
- 设置截面、材料和单元尺寸并预览网格。
- 支持选择高亮、吸附、框选、撤销和重做。

### 阶段 3：交互测点布置

- 点击梁或表面创建测点并自动计算局部坐标。
- 选择上/下表面、方向、量长和数据通道。
- 支持拖动、复制、删除、阵列和成对布置。
- 模型重新划分网格后按几何坐标恢复测点。
- 在属性面板和模型悬停提示中显示完整测点信息。

### 阶段 4：完整离线工作流

- 算法选择和动态参数表单。
- 输入完整性、算法能力和可观测性校验。
- 后台计算、进度、取消和错误定位。
- 形态、应变、应力、边界跳变、测点残差和结果探针。
- 项目保存、打开、另存和恢复布局。

### 阶段 5：CAD、壳与三维算法

- Gmsh/OpenCASCADE 导入 STEP/IGES 并生成网格。
- 在已建立的三维梁局部坐标系和曲梁测点映射上，继续增加显式截面旋转与沿路径扭转。
- 增加壳面、法向、正反面和方向性应变测点。
- 通过算法插件加入三维梁、曲梁和壳 iFEM。

### 阶段 6：实时监测与产品化

- 数据源协议、CSV 回放、串口/网络适配器和通道映射。
- 时间戳、标定、质量标记、缺失数据策略和环形缓冲。
- 增量或分帧求解、场景原位更新、暂停和历史回放。
- macOS/Windows 安装包、日志、崩溃恢复、示例项目和用户手册。

## 5. 验收原则

- 新架构不得改变现有示例的数值结果，允许误差由明确容差控制。
- 新增算法不得要求修改主窗口中的算法分支。
- 测点在保存、打开和重新网格化后仍映射到同一几何位置。
- 计算任务不能阻塞窗口交互，取消操作必须可预测。
- 三维视图切换和结果刷新不能持续增加 Actor、色标或内存占用。
- 所有项目文件均包含模式版本，并提供旧版本迁移测试。
- 发布版本必须在没有 Python 开发环境的目标机器上启动。

## 6. 关键风险

- 通用 CAD 编辑器工作量过大：首期限定为结构参数化建模，复杂 CAD 采用导入方式。
- 网格编号不稳定：测点必须附着到几何实体和局部坐标，网格 ID 仅作为运行期缓存。
- 算法差异较大：能力声明和统一结果字段必须先于第二种算法落地。
- VTK 线程限制：计算可后台执行，所有 Actor 更新统一回到 Qt 主线程。
- 大型依赖打包复杂：在开发中期建立持续打包验证，不留到最终阶段处理。
- 第三方几何库可能影响分发许可：接入 Gmsh/OpenCASCADE 前完成发布许可评估。

- 做了什么：利用左侧输入区空白增加梁长、节点分段和测点位置预览，并建立表单驱动刷新。
- 新增内容：上/下表面分层、红色矩形测点、悬停显示位置、表面和应变信息；修正早期量长色条含义不清、文字遮挡和表面对应错误。
- 可追溯提交：`f831040`、`4c1dc70`。

### 迭代 03：Qt 单前端收敛

- 做了什么：删除 Tk 回退前端，只保留 PySide6/Qt 桌面界面，避免两套 UI 长期分叉。

- 结果：后续建模、测点和三维结果功能均只需要维护一套桌面前端。

### 迭代 04：界面软件化与绘图稳定性

- 做了什么：把页面整理为“模型与输入”和“重构与观察”两个主要工作区，统一留白、卡片、层级和按钮状态。

- 修复内容：移除重构点/实测点的冗余文字指示，修复重复点击后 Matplotlib 图像持续缩小、色标重复创建以及多处字体遮挡。

### 迭代 05：截面应变与应力后处理

- 做了什么：在不改变原始求解结果的前提下，从重构自由度计算截面轴向应变和弹性应力。

- 边界说明：连续化属于显示后处理，不会把原算法的单元场改成数学上连续的解。

### 迭代 06：交互式三维结果视图

- 做了什么：接入 PyVista/VTK，将形状、应变和应力结果放入可旋转、缩放和切换视角的三维视口。
- 新增内容：二维/三维切换，等轴、正视、俯视、截面和自适应相机，原始模型/测点图层，色标和后端未安装时的明确降级提示。
- 稳定性处理：复用场景与 Actor，避免模式切换时不断叠加对象或缩小视图。

### 迭代 07：领域模型与算法插件基线

- 做了什么：把项目数据、算法协议、插件注册和分析调度从主窗口逻辑中分离。

### 迭代 08：交互建模 MVP

- 做了什么：增加独立建模对话框和二维/三维几何编辑能力，形成项目级模型数据。
- 新增内容：节点增删改、直梁和无分支空间折线梁、精确 x/y/z 输入、路径延伸/拆分、三投影视图、选择高亮、撤销重做以及 `.ifemproj` 保存和打开。
- 能力约束：当前模型可保存空间几何，但旧二维算法只对其能力范围内的模型开放运行。

### 迭代 09：解析圆弧与三维定向测点

- 做了什么：将圆弧梁作为单个参数化几何实体保存，而不是用多个折线单元冒充曲梁。
- 新增内容：XY/XZ/YZ 平面的圆心、半径、起止角建模；测点环向角、表面内测量轴角、量长、稳定附着信息和三维贴片/双向测量轴。
- 兼容处理：任意角度测点可完整建模、保存和显示；超出旧二维求解器能力时由能力校验阻止误算。

### 迭代 10：统一截面与截面感知可视化

- 做了什么：增加“整根梁采用同一截面”的定义流程，并让几何、测点和结果显示共享同一个截面几何核。
- 新增内容：矩形、圆形、圆管、矩形管、工字形五类截面，动态参数表单、二维截面预览、空心轮廓校验和项目模式 v4。
- 三维新增：沿直梁、解析圆弧和空间折线路径生成真实截面扫掠；按实际外轮廓计算测点位置、表面法向和环向切向。
- 结果新增：应变/应力结果映射到真实截面表面，测点贴片和双向测量轴随截面变化，支持截面观察相机。
- 验证结果：领域模型、项目迁移、几何核、空间建模、Qt 交互和结果数据均有自动化覆盖；该迭代完成时测试集为 43 项。

### 迭代 11：三维真实表面交互布点

- 做了什么：把 VTK 命中点转换为稳定的梁几何附着信息，打通“三维模型表面 -> 测点数据 -> 属性面板 -> 撤销/保存”流程。
- 建模层新增：`BeamSurfaceLocation`，包含梁段 ID、局部坐标、路径弧长、真实表面坐标、环向角、表面法向、环向切向和拾取误差。
- 几何新增：识别纯显示截面放大倍率，反算时恢复物理尺寸；圆弧拾取增加局部数值细化，避免折线采样产生的位置误差。
- 交互新增：“三维表面测点”模式、十字光标、悬停吸附点、弧长/环向角预览、连续点击布点和 `Esc` 退出。
- 界面优化：三维视图从“预览”升级为“建模”，长梁和曲梁按最近路径选择梁段；测点属性显示真实表面坐标、轴线坐标和路径弧长。
- 稳定性：预览复用单个 VTK Actor，不随鼠标移动累积；新增测点进入现有 `QUndoStack`，项目模式和外部 JSON 结构不变。
- 验证结果：直梁、解析圆弧、空间折线、五类统一截面、任意环向角、撤销和项目往返均有测试；该迭代完成时测试集为 49 项，并通过真实 Qt/VTK 渲染冒烟检查。

### 迭代 12：应变测量轴语义修正

- 做了什么：将测点原先带有正向暗示的单箭头统一改为以测点为中心的双向测量轴。
- 物理语义：法向应变分量满足 `ε_n = n^T ε n = (-n)^T ε (-n)`；应变数值仍可为正或负，分别表达拉伸和压缩，但测量轴的 `n` 与 `-n` 没有区别。
- 界面调整：二维建模、三维建模和三维结果视图均显示双向箭头；属性、悬停提示和图例统一使用“测量轴”，并明确 `α` 与 `α+180°` 等价。
- 兼容处理：内部仍保存单位向量和原有 `orientation_angle_degrees` 字段，算法公式、项目模式和外部 JSON 结构均未改变。
- 验证结果：增加双向轴居中及反向向量视觉等价测试；完整测试集为 50 项，并通过建模视口和应力结果视口的真实 Qt/VTK 渲染检查。

### 迭代 13：测点姿态与结果图层分离

- 做了什么：明确红色矩形贴片是应变片姿态示意，长边必须与双向测量轴完全一致；不同测点可独立设置截面环向位置 `θ` 和表面内轴角 `α`。
- 几何改进：新增可测试的表面定向贴片几何，以真实表面法向约束贴片平面，并由同一个归一化测量轴同时生成贴片长边和双向箭头，适用于管截面不同角度的测点。
- 结果调整：从三维结果视图移除“测点”图层开关、贴片、位置线和测量轴 Actor；二维和三维结果只展示结构形状、应变/应力场及必要的结构节点。
- 兼容处理：结果帧仍保留测点数据，供计算、表格、残差分析和后续探针使用；项目数据、算法输入和 JSON 结构不变。
- 验证结果：增加贴片长边/测量轴一致性和结果图层隔离测试；完整测试集为 52 项，并通过 `α=0°/45°/90°` 建模视口及无测点覆盖的应力结果视口真实 Qt/VTK 检查。

### 迭代 14：Qt 工作台视觉系统收敛

- 做了什么：结合 UI/UX Pro Max 的数据密集型桌面建议和 Taste Skill 的审计方法，对现有界面做定向演进，保留既有信息架构，不改算法和项目数据。
- 视觉调整：统一为白色基底、深鼠尾草绿主色和无衬线字体；减少嵌套卡片感，统一面板、控件和状态徽标圆角，并让应力色图与红色测点仅承担数据语义。

### 迭代 23：macOS 三维视口安全退出

- 验证结果：增加同步渲染、底层关闭、取消退出和建模对话框释放测试，完整测试集为 96 项；真实 macOS Cocoa/PyVista/VTK 双视口完成重构后正常退出，进程返回码为 `0`，两个自动渲染定时器均未启用。

- 验证结果：完成项目库列表和项目命名窗口离屏检查；新增路径覆盖、名称安全、同名阻止、损坏项目、列表选择、主窗口打开/另存、新建路径预留和建模器首次保存测试，完整测试集为 111 项。

### 迭代 29：可操作分析状态与桌面工作流精修

- 分析入口：将输入就绪徽标从被动文本改为可点击、可键盘激活的状态入口；有问题时定位并选中首个字段，无问题时直接运行。空结果视口新增“检查输入 → 运行重构 → 查看结果”三步状态和同源操作，不再让用户在空白图中寻找下一步。
- 结果安全：输入变化后保留上一轮云图和数值用于对照，但上下文条与结果区同步显示“结果已过期”；只有重新运行成功后清除，防止旧结果被误读为当前结果。
- 数据效率：结果页签显示记录数与场表示方式，只读科学表支持选择一行后以平台标准复制快捷键（`Ctrl+C` / `⌘C`）复制 TSV；`F5`、`Ctrl+1..3` 和 `Alt+1..5` 分别补齐运行、结果模式和输入页导航。
- 最小布局：降低输入预览的刚性高度，压缩结果页签与表格内边距；在 `1180×760` 下保留完整三步状态或结果图，同时显示结果表头和首行。控件补充 buddy、读屏名称与焦点说明，状态不再只依赖颜色。
- 辅助界面：项目库增加 `Ctrl+F`、Esc 清除筛选、可见数/总数、空库/无匹配恢复说明和损坏项目的可见错误；项目命名增加显式字段标签。建模器明确区分“保存项目”“应用到工作台”和“替换当前路径”，属性空态与完整实体 ID 也可选择、复制和悬停查看。
- 验证结果：完成标准工作台、最小工作台、最小建模器、启动中心和项目库离屏截图复核；新增可操作校验、过期/失败结果回滚、busy 单一状态、TSV 复制、快捷导航、项目库恢复和建模动作语义测试，完整测试集为 123 项。

### 迭代 30：ANA-001 插件恢复与字段级校验

- 项目格式：`ProjectDocument` 升级到 v6，分析工况记录算法版本和参数模式版本；v1-v5 项目继续迁移，历史项目不自动推断版本。插件参数按不透明 JSON 配置递归复制，未知字段不会因当前插件模式变化而被过滤。
- 恢复状态：项目请求的插件与当前可用候选彻底分离。插件缺失、版本变化、参数模式变化或旧参数不再有效时，原算法 ID、版本和参数保持冻结；只有用户明确采用当前版本或选择替代算法后才原子更新工况。无分析工况的项目在保存时创建活动工况。
- 服务契约：注册中心提供不回退的插件解析状态；分析服务在进入求解器前统一校验动态参数的类型、枚举、上下界和必填项，异常保留完整 `ValidationReport`，并核对结果插件 ID 与版本。
- 字段定位：模型、材料、显示、测点、约束和动态参数统一使用 JSON Pointer 字段路径。输入状态入口可按路径选择表格行、打开分组并聚焦具体编辑器；第三方插件暂未提供字段时仍保留兼容提示。
- 数据安全：拒绝 NaN/Infinity、浮点截断整数、非法测点表面/权重/量长和非 JSON 插件参数；序列化失败不会替换已有项目文件。旧二维样例位移数值保持原基线。
- 验证结果：新增项目 v5→v6、插件缺失/改绑、版本与参数模式确认、无默认值回写、非有限参数拒绝、插件界面异常事务回滚、未排序测点字段路径和真实 Qt 焦点测试；完整测试集为 164 项。

### 迭代 31：任意空间圆弧与 NURBS 几何核首版

- 空间圆弧：新增三点定义入口，由三个有序空间点精确恢复圆心、半径、倾斜平面法向和扫角；主平面与任意倾斜平面使用同一解析圆弧实体，保存后不退化为折线。
- 任意曲线：新增夹持 B 样条/NURBS 单实体，保存次数、控制点、权重和节点向量；实现稳定的点/切向求值、弧长积分和弧长到曲线参数的反求。
- 建模闭环：交互建模器增加“空间曲线…”入口，可输入三点创建空间圆弧，或输入控制点和权重创建 NURBS；替换路径可撤销，截面扫掠、表面拾取、测点方向和等弧长定位沿用真实曲线。
- 入口精修：路径快速生成器以常驻“直线 / 圆弧”分段按钮替代原生下拉菜单，数值框按有效精度显示并限制横向膨胀；当前路径摘要与生成参数分离，“追加”作为非破坏性主操作突出显示。
- 局部标架：NURBS 首版使用确定性的平行移动标架，避免扫掠截面随全局坐标突跳；显式截面转角和用户定义扭转仍归 `MOD-009` 后续实现。
- 能力边界：本轮不增加曲梁求解公式；现有二维直梁插件会按几何能力声明禁用。NURBS 控制点目前通过坐标文本输入，图形控制柄、曲线追加和混合路径交互仍待补齐。
- 验证结果：新增倾斜平面圆弧、NURBS 项目往返、弧长映射、标架连续性、表面拾取、非法次数/权重、建模器创建撤销、最小宽度路径生成器和连续追加草稿保持测试；完整测试集为 173 项。

## 8. 当前能力边界

- 截面目前是全梁统一截面；NURBS 使用自动平行移动标架，尚不支持分段截面、渐变截面、显式截面转角或用户定义的沿路径扭转。
- 曲线几何目前支持主平面/任意倾斜平面的解析圆弧和单实体 B 样条/NURBS；NURBS 的图形控制柄、曲线追加交互、分支梁和一般 CAD 曲线尚未实现。
- 三维视口可以拾取节点、梁段和测点，并支持真实表面新建、拖动、复制、对侧和等距阵列；尚不支持测点多选、分组或二维区域阵列。
- 空间梁、解析圆弧和任意角度测点可建模和保存，现有二维算法仍按能力声明限制运行。
- 几何路径与分析网格尚未完全分离，重新离散后的稳定测点映射仍需补齐。
- 数据通道、文件回放、实时采集、后台连续求解和通用结果探针尚未实现。
